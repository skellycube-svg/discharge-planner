# Mobile Wireframes - Care to Home Companion

## 💡 Why Wireframes Matter for Product Design

Wireframes are low-fidelity mockups that show exactly what goes on each screen before you write any code. They help you spot missing features, prioritize visual hierarchy, and align the team on layout. Building wireframes first prevents costly rewrites when you realize mid-development that a screen doesn't work.

### 🎯 How to Use This Information:

1. **Study visual hierarchy:** Notice what's big, bold, or colored vs. what's small and gray - copy this priority in your build
2. **Identify components to build:** Cards, buttons, lists, headers - catalog reusable components before you start coding
3. **Check mobile usability:** Are touch targets big enough? Is text readable? Can you thumb-navigate easily?
4. **Note grayscale design:** These wireframes intentionally avoid color to focus on layout and hierarchy - add color strategically
5. **Map to user flows:** Each wireframe represents a step in a user flow - build screens that connect logically
6. **Spot what's missing:** If you can't complete a user flow with these screens, you need to design additional wireframes

**⚡ Quick Rule:** If you find yourself redesigning a screen while coding it, you should have caught that in wireframes. Iterate here, not in code.

## Home Dashboard
**Category:** Core Screen
**Description:** Main landing screen with today's tasks

This wireframe shows the main landing screen with:
- Status bar with time, signal, battery
- Header with app branding and menu
- Today's progress overview
- Quick action buttons (Emergency, Medications, Call Doctor)
- Today's checklist with task items
- Upcoming reminders section
- Bottom navigation bar

### Design Principles
- **Mobile-first:** Optimized for smartphone use
- **Large touch targets:** Easy to tap while multitasking
- **Clear hierarchy:** Most important info at top
- **Visual indicators:** Progress bars, icons, color coding
- **Grayscale base:** Add color strategically for emphasis
- **Accessible:** High contrast, readable text sizes

### Key Features
- Push notifications for medications & appointments
- Interactive checklists with progress tracking
- One-tap calling for emergencies
- Save resources for quick access

## Design Guidelines

### Mobile-First Considerations
- Design for thumb-reachable areas
- Important actions in bottom 2/3 of screen
- Avoid hamburger menus for primary navigation
- Use bottom navigation bar for main sections

### Accessibility Requirements
- Minimum 44x44pt touch targets
- 16px minimum font size for body text
- WCAG AA contrast ratios (4.5:1 for text)
- Support for screen readers and voice control

### Visual Design
- Use color sparingly for emphasis and status
- Red for emergencies/warnings
- Green for completed tasks
- Blue for informational elements
- Icons paired with text labels

### Performance
- Optimize images for mobile
- Design for offline-first experience
- Show loading states for async operations
- Cache critical content locally
